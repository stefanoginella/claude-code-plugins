# codeguard status

Report the current state of a repository's safeguards — codeguard-managed
and otherwise — without writing a single file. This skill is strictly
**read-only**: no edits, no installs, no auto-fixes, no staging. If
something needs changing, the deliverable is a recommendation to run
`/codeguard:setup`, never the change itself.

## Workflow

### 1. Find what codeguard owns

- `git grep -l "generated by codeguard"` lists the tracked marker-bearing
  files; follow with a plain `grep -rl "generated by codeguard" .
  --exclude-dir=.git --exclude-dir=node_modules` (adapt the excludes to
  the repo) to catch generated files not committed yet.
- Note the version in each marker and compare against the installed
  plugin's version (this plugin's `plugin.json`). An older marker isn't
  an error — report it as "generated by v0.7, plugin is now v0.8" so the
  user can decide whether a refresh run is worth it.
- Check `CLAUDE.md` for the `<!-- codeguard:start -->` …
  `<!-- codeguard:end -->` sentinel block, and whether `CLAUDE.md` is a
  symlink (commonly to `AGENTS.md`).
- Check `.claude/settings.json` and `.claude/settings.local.json` for the
  DoD Stop-hook entry — identified by its `dod-check.sh` script path —
  and whether that script exists and is executable.

### 2. Check it still works

Presence isn't health — verify the wiring, using only read-only or
dry-run commands:

- **Hooks actually activated?** A hook config file with no installed hook
  does nothing. Look in `.git/hooks/` for the manager's shim (lefthook,
  husky, pre-commit, captainhook), and use the manager's check/dry-run
  mode from `../setup/references/git-hooks.md` — never a mode that runs
  auto-fixers against the working tree.
- **CI still present and valid?** The workflow files exist, their jobs
  still cover what the setup promised (lint/type/test, secret scan, SAST,
  dependency audit — whatever was approved), and `actionlint` passes if
  it's available.
- **DoD hook healthy?** Settings entry points at a script that exists and
  is executable, `.claude/` is not gitignored (otherwise the hook never
  reaches a fresh clone), and `.claude/.dod-attempts` *is* gitignored
  (mutable state that shouldn't be committed).
- **Tools resolvable?** The commands the hooks and CI call actually exist
  in this environment (`command -v`, or the package manager's bin dir) —
  a hook that calls a missing binary fails on every commit, which is
  usually the real answer to "why is my commit blocked?".

### 3. Compare against the catalog

With the stack known (detect it if needed via
`../setup/references/stack-detection.md`), skim
`../setup/references/safeguards-catalog.md` and note catalog items that
fit this repo's stack, stage, and exposure but aren't present. This is a
gap list, not a proposal — one line per gap, no plans, no file contents.

### 4. Report

A short report in this shape, then stop:

- **Working** — safeguards present and verified wired, one line each.
- **Drifted / broken** — present but not functioning, each with the exact
  cause: "lefthook.yml exists but `lefthook install` was never run in
  this clone" is a finding; "pre-commit not firing" is just a symptom.
  Include stale-version markers here only when the newer plugin version
  actually changes that file's behavior.
- **Missing** — catalog items that fit this repo but aren't set up.
- **Next step** — if anything is drifted or missing, point at
  `/codeguard:setup` (it inventories first and extends rather than
  replaces, so re-running it is safe). If everything is green, say so
  plainly and stop — a clean bill of health is a complete, valid result,
  not a reason to invent work.

## Rules

- **Never write.** No file edits, no installs, no `--fix` flags, no
  `git add`. The only artifact this skill produces is the report.
- **Never run a mutating verification** — no auto-fixer passes, nothing
  that touches the working tree, nothing that could trip the DoD hook
  mid-check.
- **Don't re-litigate setup's choices.** Status reports on what exists;
  whether a different hook manager would have been better is not drift.
