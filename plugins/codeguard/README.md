# codeguard

A Claude Code plugin that hardens a repository against AI-generated slop —
and plain old human mistakes — with a tailored set of git hooks, CI
pipelines, and agent-facing coding standards.

## What it does

Two skills:

- **`/codeguard:setup`** walks the repo, works out its stack (even for a
  greenfield project that only has docs so far), and proposes a concrete,
  approval-gated plan: what to add, what to change, what's already fine
  as-is. Once approved, it wires everything up — hook manager, CI jobs,
  `CLAUDE.md` conventions, and, if you want it, a Claude Code `Stop` hook
  that keeps the agent from ending its turn while checks are red.
- **`/codeguard:status`** is the read-only counterpart: it reports what's
  set up, whether each piece is still wired and working (hooks actually
  installed, CI still covering what was promised, tools still
  resolvable), and what's drifted or missing — without changing anything.

Setup leans on two layers of defense:

1. **Generation time** — coding standards written into `CLAUDE.md` so the
   agent follows the project's conventions before it writes the code.
2. **Commit / CI time** — hooks and pipelines that mechanically catch what
   slips through: formatting, lint, types, tests, secrets, vulnerable or
   hallucinated dependencies, assertion-free tests.

## What you get

The exact set is tailored to each repo and approved by you before anything
is written — but for a typical TypeScript service, an approved run
produces:

- `lefthook.yml` — fast, staged-files-only checks at commit time (format,
  lint), slower ones (types, tests) at pre-push;
- `.github/workflows/ci.yml` — lint / type-check / test with a patch
  coverage gate, plus secret-scanning, SAST, and dependency-audit jobs,
  with pinned actions and least-privilege permissions;
- linter/formatter config where none existed — existing config is
  extended, never replaced;
- a `<!-- codeguard:start -->` … `<!-- codeguard:end -->` block in
  `CLAUDE.md` with the project's commands and testing expectations;
- optionally, `.claude/hooks/dod-check.sh` plus a `Stop` hook entry in
  `.claude/settings.json` — the Definition-of-Done nudge for Claude Code
  sessions, with bounded retries so it can never trap a session.

Every generated file carries a one-line provenance marker
(`generated by codeguard v<version>`) — that's what makes re-runs and
undo mechanical.

## Install

Add the marketplace and install the plugin:

```
/plugin marketplace add stefanoginella/claude-code-plugins
/plugin install codeguard
```

## Usage

Run the skills directly:

```
/codeguard:setup
/codeguard:status
```

Or just ask — setup triggers on intent, not on a specific phrase:

```
Harden this repo against AI slop
Set up pre-commit hooks and CI for this project
Add safeguards / guardrails to this codebase
```

## How it works

Setup is an interactive, approval-gated flow — not a one-shot generator:

**detect → confirm → propose → approve → set up → verify**

It detects the stack and runtime environment, inventories what already
exists, and presents a tailored plan — add / change / remove /
leave-as-is, with a one-line "why" and the cost of every item — before
writing a single file.
See `skills/setup/SKILL.md` for the full workflow and
`skills/setup/references/` for the stack-detection signals, safeguards
catalog, and per-mechanism guides it draws on.

## Safety model

- **No writes before approval** — the plan always comes first.
- **No auto-commits** — changes are staged and summarized; committing
  stays your call.
- **Provenance markers** — every generated file is labeled, so ownership
  is explicit and undo doesn't rely on memory. Delete the marker line to
  take ownership; codeguard treats the file as yours from then on.
- **`CLAUDE.md` stays yours** — codeguard only writes inside its sentinel
  block, never touches your prose, and asks first if `CLAUDE.md` is a
  symlink.
- **Safe to re-run** — a second run inventories, extends rather than
  replaces, and reports "nothing to do" when that's the truth.

## Supported stacks

Canonical, opinionated hook/CI profiles for Node/TypeScript, Python, Go,
Rust, and PHP — see `skills/setup/references/git-hooks.md`. Any other
stack is handled too: codeguard web-searches for that ecosystem's current
idiomatic tooling instead of guessing.

## Requirements

A git repository (setup offers to `git init` if there isn't one). There
are no other hard dependencies — the optional DoD hook script prefers
`jq` for parsing but falls back to `sed` when it's absent.

## Update

```
/plugin update codeguard
```

Or enable auto-update for the marketplace under `/plugin` → Marketplaces.
Changes are tracked in [CHANGELOG.md](CHANGELOG.md).

## Uninstall

Two separate things: removing the plugin, and undoing what it set up.

**Remove the plugin** (leaves everything it set up in your repos intact):

```
/plugin uninstall codeguard
```

`/plugin disable codeguard` deactivates it without removing it. Removing
the whole marketplace (`/plugin marketplace remove stefanoginella-plugins`)
also uninstalls the plugins installed from it.

**Undo codeguard's setup in a repo** — uninstalling the plugin does *not*
touch any repo it configured. To remove the setup itself:

- `git grep -l "generated by codeguard"` lists every generated file —
  delete the ones you don't want, or delete just the marker line to keep
  a file and own it yourself.
- Delete the `<!-- codeguard:start -->` … `<!-- codeguard:end -->` block
  from `CLAUDE.md`.
- Remove the `Stop` hook entry from `.claude/settings.json` (or
  `.claude/settings.local.json`), plus `.claude/hooks/dod-check.sh` and
  the `.claude/.dod-attempts` state file.

## Scope

codeguard raises the floor — it can't judge whether code is *correct* or
solves the right problem, and it doesn't design your test strategy. It's
defense in depth beneath good specs and human review, not a replacement
for either. See the setup skill's "Scope & limits" section for the full
picture.
